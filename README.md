# Alesinx O-Air BLE

Пользовательская интеграция Home Assistant для локального управления открывателем
окна **Alesinx O-Air** через Bluetooth. Wi-Fi открывателя для управления не нужен.
Интернет используется только при получении ключей через Smart Life во время настройки.

## Возможности

- Открытие и закрытие окна.
- Кнопки микропроветривания (`MICRO`) и проветривания (`VENTILATE`).
- Получение `localKey` и `secKey` через QR-вход Smart Life прямо в интерфейсе HA.
- Диагностический сенсор последней подтверждённой команды.
- Поиск открывателя по заводскому UUID: адрес Bluetooth с Mac переносить не нужно.

Поддерживается модель с Product ID `jjhmwwetqhqa1u3z`.

## Установка

1. Скачайте репозиторий через **Code → Download ZIP** и распакуйте его.
2. Скопируйте каталог `custom_components/alesinx_ble` в каталог конфигурации HA:
   `/config/custom_components/alesinx_ble`.
3. Перезапустите Home Assistant.
4. Убедитесь, что настроена интеграция **Bluetooth**, а адаптер находится в зоне
   действия открывателя. Прокси Bluetooth должен поддерживать активные соединения.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию →
   Alesinx O-Air BLE**.

Зависимости Python Home Assistant установит автоматически.
Для обновления замените каталог компонента и перезапустите HA.
Уже настроенные окна при обновлении с 0.1.0 повторно добавлять не нужно.

## Настройка через QR

1. Выберите **Войти через QR Smart Life**.
2. Укажите телефонный код страны (например, `7`) и регион аккаунта:
   `eu` — Европа, `us` — Америка, `sg` — Сингапур, `cn` — Китай, `in` — Индия.
3. В Smart Life откройте сканер QR, отсканируйте код из формы HA и подтвердите вход.
4. Нажмите **Продолжить** в HA.
5. Выберите открыватель и закройте Smart Life, чтобы освободить Bluetooth-соединение.
   HA получит ключи выбранного устройства и проверит BLE без движения окна.
6. Для второго открывателя добавьте интеграцию ещё раз и выберите другое окно.

Пароль, User Code и ручной ввод ключей не нужны. Подтверждение QR принимается
в течение трёх минут. Если время истекло, отметьте **Создать новый QR-код**
и нажмите **Продолжить**.

QR отображается встроенным компонентом HA. Ключи запрашиваются только для выбранного
O-Air. В настройках сохраняются имя, Device ID, UUID, localKey и secKey этого окна;
облачная сессия и токен QR не сохраняются. При завершении или отмене мастера сессия
очищается. Устройство остаётся привязанным к Smart Life.

Если уже есть экспорт ключей, выберите **Использовать сохранённый JSON**.
Принимается объект устройства с полями `device_id`, `uuid`, `local_key`, `sec_key`
и необязательным `name`, либо объект с массивом таких устройств в поле `devices`.

## Положение окна

**Получение положения пока не подтверждено.** На двух проверенных O-Air запросы
DP 132 (`Opening position`), DP 119 и всех параметров возвращают подтверждение `00`,
но не значения. Это проверено и после команды открытия.

После команды интеграция запрашивает DP 132 и DP 119, а раз в минуту — все параметры.
Пока значений нет, состояние окна отображается как `unknown`, обе команды управления
доступны. Сенсор последней команды показывает подтверждение её приёма устройством,
а не достижение конечного положения. Управление вручную или из Smart Life в таком
режиме не отражается в состоянии HA.

Калибровка, остановка, установка произвольного процента открытия и сенсоры батареи,
температуры и влажности в этой версии не предоставляются.

## Подключение и проверка

Соединение открывается на время операции и затем освобождается. Операции одного
окна выполняются последовательно. При потере подтверждения команда движения
автоматически не повторяется. Ошибка последующего чтения положения не отменяет
успешно подтверждённую команду.

Если подключение не удаётся, закройте Smart Life, проверьте расстояние до адаптера
и повторите попытку. При необходимости отключите Bluetooth телефона, чтобы он
не занимал соединение с открывателем.

Проверены зашифрованные BLE-сессии с двумя O-Air и фактическое закрытие/открытие
одного окна. `MICRO` получил подтверждение BLE; `VENTILATE` использует значение
из существующего профиля устройства и отдельно движением пока не проверен.

Проверки выполнялись с Home Assistant **2026.10.4**, Python **3.14.10** и Bleak
**3.0.2**. Создание QR проверено через настоящий Smart Life API; переходы форм,
получение ключей, ошибки и отмена покрыты автоматическими тестами.
Полный QR-вход через браузер на сервере HA владельца и работа через ESPHome proxy
пока не проверялись.
